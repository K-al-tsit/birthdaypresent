## 怎么修改

在 `assets/content.js` 搜索右侧表格的字段名，改双引号内的内容即可。字段路径例如 `copy.hero.lead` 表示 `copy` 内的 `hero` 内的 `lead`。

```js
"lead": "把这句话替换成你想说的话。"
```

- 保留逗号、括号和字段名；只改引号里的字。
- 两行之间写 `\n`，例如 `"第一行\n第二行"`。
- 文字中的英文双引号需要写成 `\"`；也可以直接使用中文引号“”。
- 提示中的 `{no}`、`{current}`、`{duration}` 会自动替换，请保留。
- 所有文字按纯文本显示，不要放 `<br>` 等 HTML 标签。

## 21 首歌逐首编辑

`tracks` 是按播放顺序排列的 21 个对象，每首歌都已单独列出。搜索 `"no": "01"` 找第一首，`"no": "21"` 找最后一首。

| 字段 | 用途 |
| --- | --- |
| `no` | 卡片和播放器的编号，建议保留两位数字 |
| `title` | 歌曲名，同时用于卡片、播放器和支持媒体控制的设备界面 |
| `subtitle` | 卡片的小字，可写歌手或这首歌的意义 |
| `note` | 写给她的话：全屏播放器中放在类似歌词的主阅读区域；底部播放器只显示截断后的短预览。支持用 `\\n` 主动换行 |
| `media` | 已上传到 COS 时设为 `true`；程序会自动根据“歌手 - 歌名”生成 MP3/LRC 地址 |
| `file` | 可选。只有 COS 文件名不等于“歌手 - 歌名”时才填写文件名主体，不含扩展名 |
| `src` | 仍支持手工指定完整音频地址；一般不再需要填写 |

音频根目录统一写在 `settings.audioBase`。全局歌词提前量写在 `settings.lyricsLeadSeconds`，当前为 `0.5` 秒，用来补偿这批 LRC 整体略慢的情况。对于 `media: true` 的歌曲，程序默认用 `subtitle + " - " + title` 生成文件名，并做 Unicode NFD 规范化后自动拼出 `.mp3` 与 `.lrc`。这与当前 COS 中从 macOS 上传的日文文件名兼容；如某一首命名特殊，可单独用 `file` 覆盖。

封面不需要额外填写字段。网页会从自动生成或手工指定的 MP3 中读取 ID3v2 的 `APIC` 嵌入封面，并显示在歌曲卡片、底部播放器以及支持 Media Session 的系统媒体界面中。LRC 使用 `[mm:ss.xx]` / `[mm:ss.xxx]` 时间戳；非 LRC 元数据行会被忽略。

选择一首歌后默认打开沉浸式全屏播放器；左上角向下箭头可收起到底部迷你播放器，点击迷你播放器的封面/标题区域可重新展开。切换形态不会中断当前音频，也不会重置播放进度。桌面端左侧保留封面/控制，并用乱序与顺序播放两个模式键切换播放顺序；右侧顶部提供“想对你说 / 歌词”两个选项，可点击切换。手机端默认显示大封面，在进度条上方均匀排列“乱序播放 / 想对你说 / 歌词 / 顺序播放”四个入口；“想对你说”保持文字按钮，“歌词”使用图标。默认、想说、歌词三种视图共享同一个固定高度的上部舞台，下方四个模式键、进度条和播放控制固定在同一位置，不随模式切换上下移动；整体密度回调到较紧凑的默认播放器布局。进入想说或歌词模式后，封面缩到左上角、歌曲信息移动到顶部，中间分别显示 `note` 或同步歌词；返回默认模式时封面从左上角扩展回大封面。从歌单卡片进入全屏时，卡片会从原位置拉伸铺满屏幕，再与全屏播放器完成交接；系统开启“减少动态效果”时会跳过这段转场。

若音频来自 COS 等跨域地址，JavaScript 读取 ID3 需要该存储桶允许网页域名进行 CORS `GET` 请求；播放器本身能播放但封面不显示时，优先检查 COS 的跨域配置。代码会使用单段 `Range` 请求优先只读取文件开头的 ID3 数据，而不是为了封面主动下载整首歌曲。

示例（替换第一首的对象，不是追加到文件末尾）：

```js
{
  "no": "01",
  "title": "你的歌名",
  "subtitle": "歌手 · 一起听过的那一天",
  "note": "写给她的一句话",
  "src": "https://你的音频域名/01.mp3"
}
```

若将来增减歌曲数量，程序会按 `tracks` 自动渲染，但正文里的“21”、`copy.playlist.title`、专辑封面数字等是刻意保留的文案，需要在相应字段手动改。

## 自动昼夜与本地预览

- 自动：按访问者设备本地时间判断；06:00（含）至 18:00（不含）为晴空，其余为黄昏。不会请求定位，也不是根据日出日落计算。
- 在 `settings.dayStartHour` 和 `settings.duskStartHour` 修改整数小时；请保持 `0 ≤ 白天起点 < 黄昏起点 ≤ 24`。
- 右上角可选择“自动 / 晴空 / 黄昏”。手动选择保存在当前浏览器；要恢复随时间切换，选择“自动”。
- 页面每分钟、以及从后台回到前台时检查一次时段。设备时钟和时区会影响自动结果。
- 临时预览：[晴空](http://localhost:8765/?theme=day) / [黄昏](http://localhost:8765/?theme=dusk)。参数不会覆盖已保存的偏好；手动选择后会移除参数。
- `动画 开 / 关` 控制专辑封面的轻微漂浮动画，不是音量开关。系统启用“减少动态效果”时停止动画。

## vivo X100s 手机端验收

- 首要目标设备：vivo X100s，竖屏优先；同时兼容约 360–460 CSS px 的 Android 手机视口。
- 手机顶部只显示一个 44×44 的时段图标按钮；点击后展开“自动 / 晴空 / 黄昏”和动画开关，避免顶栏拥挤。
- 全屏播放器在大封面模式下，封面下方、进度条上方排列乱序图标 / “想对你说”文字按钮 / 循环图标；“想对你说”不使用图标，点击后切换为紧凑封面 + 顶部歌曲信息 + 中部正文。
- 底部播放器的上一首 / 播放 / 下一首均保持至少 44×44 的触控区域，主播放键为 48×48。
- 播放进度条使用 6px 轨道和 20px 拖动圆点，并保留约 48px 的实际触控高度。
- 播放器保留 Android / iPhone 底部安全区兜底；即使 `env(safe-area-inset-bottom)` 返回 0，也仍有固定底部间距。
- 360–460px 视口额外收紧首屏标题、专辑封面和卡片尺寸，重点避免 X100s 竖屏上的拥挤和横向溢出。
